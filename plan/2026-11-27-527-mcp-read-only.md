# Plan: Support read-only MCP sessions

## Approved design

In `cmd/mcp/main.go`, give each stdio tool an explicit mutation classification and use it for both discovery and dispatch. Add `--read-only` and a deployment setting, retain the operational default for existing clients, and set read-only mode explicitly in new installation examples and managed entry points. In normal mode, advertise MCP annotations for read and write behavior. Add an opt-in read-only scope to tenant Viewer service-account credentials. Enforce a default-deny allowlist of verified read routes for that scope in `pkg/api/auth_middleware.go`, including checks for side effects regardless of HTTP method. Preserve existing credentials' behavior. Keep `pkg/api/mcp_http.go` on its current curated read-only surface.

### Alternatives rejected

Filtering only tools/list leaves direct calls available. MCP annotations and prompt-level approval are advisory and cannot enforce API authorization.

## Implementation details

- The stdio process uses `FIDES_MCP_READ_ONLY`. An explicit `--read-only` flag takes precedence. An invalid environment value stops startup when the flag is absent. New examples pass `--read-only` explicitly. The standalone default remains disabled. Classified tools advertise annotations in both modes. Stdio negotiates MCP 2025-03-26 for annotation support and accepts 2024-11-05 clients.
- A Viewer service account gets a scoped key through the issuance request's `read_only: true` field or the CLI's `issue-key --read-only` flag. The CLI checks the returned scope before displaying the key. Migration `0031_service_account_key_read_only.sql` defaults existing keys to unscoped. Scoped keys neither inherit approval delegation nor update their usage timestamp.
- Scoped API requests allow the GET routes for flows, environments, policies, compliance, artifact and attestation search, controls coverage, deployment frequency, and ServiceNow grounding. The existing read-only HTTP MCP dispatcher remains accessible via POST. Other authenticated routes return 403. ServiceNow status and CMDB lookup can mint OAuth tokens, so these tools require a write-capable session.
- New-install examples are in the MCP guides, README and feature guides, the walkthrough, and the published `llms-full.txt` copy. The MCP guides document mixed-version rollout and key revocation before rollback.

## Risks

Tool classification can drift as new tools are added. Require explicit classification before a tool enters the registry. New-install configuration must remain distinguishable from an upgrade.

## Rollback

Keep scoped credentials enforcing their stated scope. Revoke or safely retire those credentials before reverting to code that cannot enforce it. Keep scope records and existing installation settings.
