# Spec: Support read-only MCP sessions

## Design

In `cmd/mcp/main.go`, give each stdio tool an explicit mutation classification and use it for both discovery and dispatch. Add `--read-only` and a deployment setting, retain the operational default for existing clients, and set read-only mode explicitly in new installation examples and managed entry points. In normal mode, advertise MCP annotations for read and write behavior. Add an opt-in read-only scope to tenant Viewer service-account credentials. Enforce a default-deny allowlist of verified read routes for that scope in `pkg/api/auth_middleware.go`, including checks for side effects regardless of HTTP method. Preserve existing credentials' behavior. Keep `pkg/api/mcp_http.go` on its current curated read-only surface.

## Alternatives rejected

Filtering only tools/list leaves direct calls available. MCP annotations and prompt-level approval are advisory and cannot enforce API authorization.

## Risks

Tool classification can drift as new tools are added. Require explicit classification before a tool enters the registry. New-install configuration must remain distinguishable from an upgrade.

## Verification

Test tool discovery and direct calls in each mode, annotations in negotiated responses, and that a read-only service credential is accepted for reads and rejected for mutations using actual API authorization.
